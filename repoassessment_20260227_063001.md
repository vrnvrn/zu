**Date:** 2026-02-27

## Repository Overview

This is a **Next.js 14 + GitHub-based newsletter system** for Zuzalu community:
- Blog/Newsletter archive for published articles
- Crossword puzzles (currently archived)
- Editor dashboard (proof of concept)
- GitHub-native data storage (Issues, Markdown files)

## Scalability Issues Identified

### 1. Inconsistent Content Storage
- **Location:** `public/newsletters/` vs `app/archive/` vs GitHub remote
- **Issue:** Three different places for "archived" content
- **Impact:** Hard to maintain, no single source of truth
- **Files:** 
  - `zuletter/public/newsletters/`
  - `zuletter/app/archive/`
  - GitHub remote via `fetchNewsletters()`

### 2. Newsletter Editions Mixed with App Routes
- **Location:** `app/january-2026/`, `app/february-2026/`
- **Issue:** Newsletter content is stored as Next.js routes instead of content
- **Impact:** Routes are code, content should be separate
- **Files:** `app/january-2026/page.tsx`, `app/february-2026/page.tsx`

### 3. Flat Image Organization
- **Location:** `public/newsletters/images/2026-01/`
- **Issue:** All newsletter images in flat directories
- **Impact:** Will become messy at scale with multiple years/months

### 4. Hardcoded Crossword Data
- **Location:** `app/crossword/page.tsx:7-48`
- **Issue:** Answer key, clues, and grid hardcoded in page component
- **Impact:** No separation of content from code; can't archive multiple crosswords

### 5. Editor Uses Mock Data
- **Location:** `app/editor/page.tsx:15-56`
- **Issue:** Hardcoded sample items, not connected to real workflow
- **Impact:** Not usable for actual editorial work

### 6. No Pagination
- **Location:** `app/archive/page.tsx`, `app/page.tsx`
- **Issue:** All items loaded at once
- **Impact:** Performance issues as content grows

### 7. Scattered Data Fetching Logic
- **Location:** `lib/github.ts` (500 lines)
- **Issue:** All data fetching in one file, mixed concerns
- **Impact:** Hard to maintain, test, and extend

### 8. No Content Index Files
- **Issue:** No JSON manifest for content listings
- **Impact:** Can't do efficient pagination or random access

### 9. Duplicate Newsletter Data Sources
- **Location:** 
  - `lib/newsletter-content.ts` (local)
  - GitHub remote via `fetchNewsletters()`
  - Local filesystem via `fetchLocalArchiveNewsletters()`
- **Issue:** Multiple ways to get newsletter data
